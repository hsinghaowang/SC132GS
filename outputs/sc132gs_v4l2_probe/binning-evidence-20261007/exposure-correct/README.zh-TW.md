# Linear binning 60 FPS：曝光與顯示亮度修正

2026-10-07，以室內物體細節為優先。現場同時有亮窗與暗室內，未使用灰卡校準。

後續已啟用 binning 60 FPS AE，現行設定與驗證見 [AE 驗證](../ae60-validation/README.zh-TW.md)。以下保留手動曝光階段的比較紀錄。

## 原因與修改

原本 BayerLuma 產生 0..255 的線性灰階，直接寫入標示 colorimetry=bt709 的 NV12。缺少線性到 BT.709 的轉換，而且 0..255 未對齊 BT.709 的 16..235 視訊範圍，會讓暗部顯示過暗、部分黑階被解碼裁掉。

新 LinearVideoLuma 只在實驗 Linear 模式送進編碼器的 Y plane 上套用固定 LUT：

- L < 0.018：E = 4.5 L；其餘 E = 1.099 L^0.45 - 0.099。
- Y = round(16 + 219 E)。UV 維持 128。
- 不做逐幀直方圖拉伸，不修改感測器 RAW 或原先 AE 的量測輸入。
- 這是灰階顯示轉換；不是完整彩色 ISP、黑階校準或 HDR 重建。固定曝光仍未啟用 AE。

參考：[GStreamer video color](https://gstreamer.freedesktop.org/documentation/video/video-color.html)、[Linux V4L2 colorspace definitions](https://kernel.org/doc/html/v5.7/media/uapi/v4l/colorspaces-defs.html)。

## 目前保留設定

- 每眼 544×640，合成 1088×640。
- VTS 2700，曝光 2400 rows，依既有時序估算約 14.8 ms。
- 兩眼 analogue_gain index 0，寄存器 0x0320（最低增益）。
- 服務 sc132gs-binning60-rtsp，使用 build-exposure60/stereo-h265-rtsp。
- RTSP：rtsp://192.168.137.226:8554/stereo。
- AE 關閉；這組固定設定適用目前室內場景，光線變化後仍需調整。
- 服務與實驗模組仍為暫時部署，未新增開機自動載入。

## 實際解碼比較

曝光全部固定 2400 rows；各次 snapshot 是當時畫面，不是受控光度實驗。

| 顯示路徑 | gain index / code | 中央 ROI 平均 | 中位數 | <=5 比例 | >=250 比例 | 實際 PTS FPS |
|---|---|---:|---:|---:|---:|---:|
| 原線性直接送編碼 | 0 / 0x0320 | 47.14 | 27 | 13.28% | 3.88% | 60.0015 |
| 原線性直接送編碼 | 28 / 0x2320 | 83.19 | 59 | 6.46% | 5.23% | 59.9988 |
| 原線性直接送編碼 | 60 / 0x2720 | 138.78 | 127 | 2.67% | 19.47% | 59.9967 |

| 修正 BT.709 | 28 / 0x2320 | 139.26 | 126 | 0% | 3.98% | 59.9998 |
| 修正後最終 15 秒驗證 | 0 / 0x0320 | 109.02 | 96 | 0% | 3.22% | 59.9988 |

最終軟體解碼 893 frames、893 個不同 RGB hashes；有實際室內細節，亮窗仍局部過曝。顯示曲線改變後，平均亮度提升不代表感測器收到更多光，也不代表 RAW 的訊噪比提高。<=5 比例為零不等於全部暗部都有可用紋理。

編譯完成，CTest 5/5 通過；新測試檢查 BT.709 黑白端點、18% 灰、低光斜率及 LUT 單調性。最終 decoded.png 可直接檢查結果。

目前約 14.8 ms 曝光造成的動態模糊仍存在；這次以靜態曝光與顯示亮度為主，未重新驗證揮手或辨識模型。
